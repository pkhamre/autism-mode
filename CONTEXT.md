# Autism Mode

Autism Mode is a communication-mode product centered on autistic readers while remaining useful to anyone who prefers explicit communication. This glossary defines the language used to describe its behavior.

## Activation

**Autism Mode**:
A conversation-persistent communication mode that makes decision-relevant meaning explicit. It expands meaning rather than shortening output.
_Avoid_: Autism-friendly mode, explicit-communication mode

**Reader**:
The person receiving an agent response and controlling whether Autism Mode is activated, tuned, or deactivated.
_Avoid_: User, recipient, person

**Explicit Activation**:
A clear request to enable Autism Mode as a whole for the current conversation. A request for one of its behaviors is not Explicit Activation.
_Avoid_: Trigger, semantic activation

**Behavior Request**:
A request for one Autism Mode behavior without a request to enable Autism Mode as a whole. A Behavior Request applies through the current task and does not persist across an unrelated topic change.
_Avoid_: Implicit activation, partial activation

**Deactivation**:
An explicit Reader request to leave Autism Mode. It may use the word "autism" or any unambiguous equivalent, and it is confirmed in one line.
_Avoid_: Tuning, pause

**Disclosure**:
A statement that the Reader is autistic. A Disclosure is not, by itself, a request to enable Autism Mode.
_Avoid_: Activation signal, trigger phrase

**Tuning**:
An explicit Reader instruction that changes one or more Autism Mode behaviors while leaving the mode active. Tuning lasts until deactivation or the conversation ends.
_Avoid_: Partial deactivation

## Knowledge Boundaries

**Fact**:
A claim supported by direct observation or completed verification.
_Avoid_: Known truth, certainty

**Reported Claim**:
An event or condition stated by the Reader but not independently verified by the agent. The report itself is a Fact; its content remains unverified.
_Avoid_: Fact, inference

**Inference**:
A conclusion drawn from available evidence but not directly verified.
_Avoid_: Assumption, fact

**Uncertainty**:
An explicit boundary on what is unknown or how strongly a claim is supported.
_Avoid_: Inference, ambiguity

**Assumption**:
A premise deliberately accepted so work can continue without verification.
_Avoid_: Inference, fact

**Ambiguity**:
The presence of multiple plausible meanings that could lead to different responses or actions.
_Avoid_: Uncertainty

## Decisions

**Delegated Judgment**:
Explicit permission from the Reader for the agent to choose among non-destructive interpretations. The chosen interpretation and rejected alternatives remain visible.
_Avoid_: Unrestricted permission

**Low-Impact Ambiguity**:
Ambiguity where choosing incorrectly is inexpensive to reverse and unlikely to cause meaningful harm. The agent may choose and continue when the choice is visible.
_Avoid_: Low-cost ambiguity, harmless ambiguity

**High-Impact Ambiguity**:
Ambiguity involving possible data loss, destructive action, security or privacy changes, spending, external publication, schema changes, breaking public contracts, or another consequence that could cause meaningful harm or be difficult to reverse. Unknown impact is High-Impact Ambiguity until clarified.
_Avoid_: Consequential ambiguity, irreversible ambiguity

**Scope Boundary**:
An explicit statement of what a modification or plan will change and what it will not change.
_Avoid_: Scope

**Completion Condition**:
An observable result used to determine whether planned or modification work is done.
_Avoid_: Done state, success criteria

**Plan Change**:
A departure from a previously stated approach. A Plan Change names the previous approach, the reason it no longer works, the replacement, and the consequences.
_Avoid_: Adjustment, refinement
